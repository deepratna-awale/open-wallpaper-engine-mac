- **Project:** MG4's root-motion box (models_gt/mg4/we_import_project, copied to p509e_box).
- **Edits:** Model Editor -> Animation -> clip "Scene (Clip 5)" -> Clip options. Set "Motion root bone" = None, then "Frame offset" 0 vs 10. Start 0, End 30, Match loop on.
- **Model json:** editor.clips[0] gets "frameoffset": 0 / 10, "rootmotion": "". id 26 is unchanged, motionflags 47104.
- **.mdl:** both 9533 bytes, with a **single byte difference at 0x2530**. The clip record's u32s read `00000000 1e000000 0a000000 ffffffff` = start 0, end 30, **frame offset 10**, root bone -1 (None). That confirms (u0 start, u1 end, u2 frame offset, u3 root bone).
- **Playback** (RenderDoc stills, animation layer on clip 26, MG4 camera): box centroid (px) at t = 0.25 / 0.5 / 0.75 / 1.0 s:
  - offset0:  (957,560) (895,540) (830,522) (753,503)
  - offset10: (829,522) (756,503) (956,560) (913,545)
- **Interpretation:** offset10 at time t matches offset0 at about t+0.5 s; the loop wraps earlier. So the frame offset **shifts the loop phase forward**: playback starts partway into the clip. It is not a delay.
  - The measured shift (about 0.5 s) is larger than 10 frames (0.33 s). Per-load timing jitter between the two captures is about +-0.15 s, so this is consistent with starting 10 frames in.

- **MDLS0004, 6 nodes** (name: flags, parent):
  - RootNode: 0, -1
  - Rig: 0, 0. Rig's matrix carries the FBX unit conversion: scale 100 and a -90 deg X turn.
  - root: 1, 1
  - mid: 1, 2
  - loose: 1, 2. It is unweighted, a child of root.
  - tip: 1, 3
- **Pivot (the empty above Rig) is not in the .mdl at all.** It is in the FBX (the string occurs 3 times), but WE's importer dropped it. Rig's parent is RootNode directly.
- **Flag 0x1 therefore means "an armature bone", not "a bone with weights".** loose and tip have no weights but have flag 1. Only the non-bone nodes (RootNode, the armature object Rig) have flag 0.
- **MDLA0006:** one animation "Scene", 30 fps, 30 frames, with **6 tracks, one per node in node order, flag-0 nodes included**, 31 keys each (pos3, rot3 euler, scale3).
  - Only mid's track varies; its rot X goes to 0.6 at key 15.
  - RootNode's track is identity throughout.
  - Rig's track is constant (rot X -1.571, scale 100), i.e. its bind.
  - So flag-0 nodes do have tracks, but constant ones equal to their bind. A playback clip could not show whether WE animates a flag-0 node, so none was taken.
