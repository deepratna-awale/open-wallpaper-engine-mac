548: clipping masks with genericimage4 (WE 2.8.0.42)

## Setup
- **Rig:** the 532c rig (purple circle = Limb 21 with maskA painted over the red rectangle = Limb 20), copied to p548_clip with materials/circle_rect.json **shader genericimage2 -> genericimage4**.
- **Clip id 29:** circle bone origin x 0 -> +275 -> 0 over 2 s, so the circle passes over the rectangle.
- **Variants** (the editor saved each .mdl/.json; make_548.py builds runtime projects with an animation layer on clip 29):
  - **c_mask_on:** clippingmasks [{id 40, invert false, hidemaskgeometry false}], circle island clippingmaskid 40
  - **c_invert:** invert true
  - **c_hide:** hidemaskgeometry true
  - **c_mask_removed:** "Remove Clipping Mask" on the circle; island ids 0,0 (the maskA entry stays in the list)

## Result (RenderDoc stills at 0.25 / 0.6 / 1.0 s; sheet_548.png)
- **The material shader decides it.** The same static rig with genericimage2 (p532c) draws the circle in full; with genericimage4 the circle disappears when it is off the rectangle (stills/mo2_548_on_gi2 vs on_gi4, sheet_on.png). The editor preview also hides it once the material is genericimage4.
- **mask_on:** the circle is visible **only where it overlaps the painted area** (the rectangle): nothing at 0.25 s, a sliver at 0.6 s, the full overlap at 1.0 s. It is drawn over the rectangle.
- **mask_removed:** the circle is drawn in full everywhere (control).
- **invert:** the circle is visible **only outside** the painted area. Where it overlaps the rectangle it is cut away and the rectangle shows; off the rectangle it is fully drawn.
- **hide (hidemaskgeometry):** the **rectangle (the geometry under the mask) is not drawn**. The circle is still clipped to the rectangle's area, so you see a circle cut to the rectangle's shape floating on the background.

## Draw list (one frame of c_mask_on: rd_draws_report.txt, inspect/inspect_report.txt, inspect/*.png)
1. **eid 25** DrawIndexed(516): the **non-clipped limb (the rectangle)** to the swapchain. SRV0 = albedo (512x256 RGBA).
2. **eid 46** DrawIndexed(516): **mask write**. The same rectangle geometry is drawn into a **half-resolution R8 render target (960x540 R8_UNORM)**. SRV0 = albedo, **SRV1 = the painted mask texture (512x256 R8)**. The mask texture is sampled in the mask-owner limb's UV space and rasterised at its screen position.
3. **eid 66** DrawIndexed(414): **mask read**. The **clipped limb (the circle)** to the swapchain. SRV0 = albedo, **SRV1 = that 960x540 R8 target**, sampled in screen space.
4. Then 4 fullscreen Draw(3) (bloom/composite).
- So the mask is **screen-space**: the mask-owner limb renders mask.r (times its own coverage) into a half-res R8 buffer, and the clipped limb scales its alpha by that buffer (or its inverse, for invert) at its screen position.
- Passes 2 and 3 use their own shader pairs (270/271 and 266/267), distinct from the plain pass (264/265). Constants are in inspect_report.txt.
- With hidemaskgeometry, pass 1 is presumably skipped while pass 2 still writes; not captured separately.

## Nested mask (make_548_nest.py, project p548_nest; nested/)
- **Image abc.png** (genericimage4), three separate islands: **A** red square (20-180), **B** green circle (centre 260,128, r 50), **C** blue square (370-420).
- **Bones:** A root > B > C. Clip 65 keys at frame 0 only: B origin x -90 (half onto A), C x -100 relative to B (onto B's right side). Played with **rate 0**.
- **Masks:** **maskA** (id 34) painted over A, assigned to B. **maskB** (id 50) painted over B's area, assigned to C. A has none.
  - Json `vertexislands[].clippingmaskid = [50, 0, 34]` (island order is C, A, B).
  - **Limb numbers do not follow image order:** Limb 20 = C, Limb 21 = A, Limb 22 = B. My first assignment hit the wrong limbs; it was fixed, and the files here are the corrected ones.
- **Result** (sheet_nested.png; stills mo2_548_nest_f0 / nest_rest):
  - **A** is drawn in full.
  - **B** is visible only where it overlaps A (the left half of the circle).
  - **C** is visible only where it lies inside maskB at B's current screen position. That **includes the part of B's area that B itself lost to A's mask** (C shows to the right of A's edge, where B is cut away).
  - So nesting is **not cumulative**: each mask is written from its owner's geometry, and is not reduced by the owner's own clipping.
  - At rest (no clip): only A is visible; B and C are off their masks.
- **Draw list** (nested/rd_draws_report.txt, nested/inspect/inspect_report.txt):
  1. eid 25 DrawIndexed(636): A, plain, to the swapchain.
  2. eid 46 DrawIndexed(636): write maskA into the 960x540 R8 target (SRV1 = maskA texture), using A's geometry.
  3. eid 66 DrawIndexed(396): B to the swapchain, reading the R8 target.
  4. eid 88 DrawIndexed(1032 = 636 + 396): write maskB into the **same R8 target** (SRV1 = maskB texture). It draws 1032 indices, i.e. both A's and B's ranges, not only B's.
  5. eid 108 DrawIndexed(150): C to the swapchain, reading the R8 target.
  - **One R8 target is reused:** each mask is written just before the limbs that read it.
